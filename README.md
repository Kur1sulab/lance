# 朗基努斯 · Lance —— 安全验证的编排层

把「下一步验证哪儿」和「怎么验证」拆成两个独立进程。

        ┌──────────────────────────────────────────────────────┐
        │ 朗基努斯 · Lance          决策 · 可带 AI             │
        │ 只产出 action JSON，从不接触目标                     │
        └──────────────────────────────────────────────────────┘
                                    │ 只传 JSON
        ┌───────────────────────────▼──────────────────────────┐
        │ litmus2                    执行 · 零 AI              │
        │ 模板匹配 / 三态覆盖 / 证据 / replay                  │
        └──────────────────────────────────────────────────────┘

拆开的理由很实际：**客户要的是一个能被独立复核的结论**。
如果 AI 直接判定"这是缺陷"，报告就失去了可审计性；
但让 AI 决定"先复核哪一条"，既省脑子，又不影响结论的确定性。

## 名字

《新世纪福音战士》里，朗基努斯之枪是唯一能贯穿 AT Field（绝对领域）的东西 ——
整个世界观里所有防御的底座，在它面前等于不存在。

借的不是那个画面，是那支枪的四件事，每一件都落在这里的一条硬约束上：

1. **没有"中途"这一层。** 枪掷出即到达，不经过任何能被拦截的中间环节。
   所以决策层到执行层只有一次 action JSON 递交：不落库、不排队、不经 shell、
   不给任何一方留"半路改主意"的窗口。

2. **它的对手是我们自己的盾。** AT Field 就是我们自己的终端态势防御产品线，
   这把枪是与之成对的矛。产品线内部先互打，比等别人来打更早知道哪一层漏。

3. **只有一支。** 战场上没有第二支可以试。所以每条动作必须带 why、必须可复核；
   宁可这轮不编排，也不用无理由的重试堆出流量。

4. **插进去就是永久痕迹。** 枪插在初号机身上，谁都可以去看。
   对应账本 JSONL：每条决策的 why、每条执行的 verdict 全部落盘，
   事后逐条回放 —— 留痕不是炫耀，是为了能被别人审。

名字是借来的，纪律是自己写的。上面四条里任意一条被代码违背，这个名字就名不副实。

## 三个命令

```bash
# 只出计划，不执行 —— 适合先看 AI 想干什么
lance next -f findings.json -brain rules|llm [-budget 8] [-out actions.json]

# 只执行，不决策 —— 适合人工审过 plan 之后再跑
lance exec -a actions.json -litmus <litmus 路径> -findings findings.json

# 决策-执行-记账 闭环，跑到收工
lance loop -f findings.json -litmus <litmus 路径> [-brain rules|llm] [-rounds 4]
```

## 对比基准（bench）

「上了 AI 到底有没有变好」用数据回答，不靠感觉：

```bash
lance bench -f findings.json [-budget 8] [-brain rules,llm] [-out .lance/bench]
```

同一份 findings（含覆盖表）分别喂 rules 与 llm，两档输入完全一致、都不带账本历史。
每档记录动作条数、kind 分布、签名集合（与账本同格式）与 Decide 耗时；两档都跑出
结果时计算签名交集/差集/重合率（交集÷并集，保留两位小数），落
`<out>/bench-<时间戳>.json` 并打印人读摘要。

llm 未配置时该档标记 `unavailable` 继续跑，不报错退出 —— 现场断网也能出报告。
此时不计算重合率：拿不可用档位的空集去对比会得出「0% 重合」的假结论，
产物里 `diff` 为 null 并在 `diff_note` 注明原因。

## 动作白名单

AI 能输出的**全部**动作，没有第六种：

| kind | 参数 | 含义 |
|---|---|---|
| `replay` | `id` | 复核一条已有发现 |
| `run_tpl` | `target`、`tpl` | 用模板打一个新目标 |
| `rerun` | `targets`、`intensity` | 换强度重跑一轮（`targets` 可留空，自动取 findings 里的目标） |
| `stop` | — | 收工 |

## 护栏（都有测试守着）

1. **未知动作直接拒** —— 模型想输出 `shell`/`exec` 一律拦掉
2. **参数白名单** —— `replay` 多带一个 `cmd` 就整批拒
3. **整批原子性** —— 一批里有 1 个非法，全部不执行（避免现场变成说不清的中间态）
4. **必须写 why** —— 没有理由的决策无法审计，拒绝执行
5. **不经 shell** —— 执行器只用 `exec.Command` 的参数数组，模型构造不出管道和第二条命令
6. **conf 越界拒** —— 0~1 之外直接拒

## 决策脑可替换

| brain | 依赖 | 场景 |
|---|---|---|
| `rules` | 无 | 默认。断网、离线内部网络、模型不可用时的兜底 |
| `llm` | OpenAI 兼容接口 | 有网时用云端模型；内部网络可用本地 Ollama |
| （待做）`static` | 无 | 外面想好 plan.json，带进内部网络执行 |

配 LLM：
```bash
export LANCE_LLM_BASE=http://127.0.0.1:11434/v1   # 或任何兼容端点
export LANCE_LLM_KEY=xxx
export LANCE_LLM_MODEL=qwen2.5:7b
```
没配就自动回落 `rules`，不会因为没模型就跑不动。
老环境不用动：`LAUGHING_LLM_*` 与更早的 `ORCH_LLM_*` 仍在读取列表里（新名优先）。

## 记账

每一条决策和执行结果追加到 `.lance/lance-ledger.jsonl`：

```json
{"ts":"...","round":1,"brain":"rules","kind":"replay",
 "signature":"replay:LS-001","why":"severity=high ...",
 "verdict":"reproduced","detail":"仍可复现"}
```

下一轮读回历史当上下文 —— **不依赖任何模型的记忆**，这解决的是
"AI 跑到一半忘了自己干过什么，把同一个目标重复打三遍"的老毛病。

## rerun 怎么取目标

规则脑发现「覆盖表里有 skip 项」时会发一个只带强度的 `rerun`，不带目标 ——
目标从哪儿来，是这条动作能不能用的关键：

1. 动作里显式给了 `args.targets`（逗号、分号、换行、空格分隔都认，自动去重）
2. 没给就退回 `-findings` 指的 findings.json，取里面出现过的 target（去重 + 排序，
   保证同一份 findings 拼出同样的命令行，历史去重才不会失效）
3. 两条路都没有 → 直接报错停下，不猜目标

单轮上限 64 个：一口气扫上百个目标跑不完，也会把时间预算全烧在第一个网段上。

结论不看文案，只解析 litmus `--json` 末尾的摘要：有命中判 `reproduced`，
零命中判 `unverified`（这轮没东西可复现，不等于「已消失」）。
产物落在 `<out>/rerun-<时间戳>/`，不和上一轮互相覆盖。

## 出站净化（对接外部推理通道）

决策层会把「发现了什么、还剩哪些没覆盖、之前做过什么」拼成 prompt 发给模型。
有些第三方通道会在入口做内容审查，安全类措辞直接返回 400，整轮决策作废；
而这三件事用中性词汇完全可以表达。所以出站前过一遍词表：

- **只洗出站**。本地账本 `lance-ledger.jsonl`、产物、日志一律保留原词，审计链不受影响。
- 词表在 `internal/sanitize/sanitize.go`，改那一个文件就够，调用方不要零散写替换。
- 规则按匹配串长度倒序应用（长词优先：组合词整体替换，不会被更短的词先吃掉半截）；ASCII 词走词边界
  匹配，`C2` 不会误伤 `abc2`，`payload` 不会误伤 `payloadx`。整体幂等。
- 关掉：`LANCE_LLM_SANITIZE=0`（接本地自建模型做 A/B 对比时用）。

prompt 是运行时拼的，看不见就只能猜，所以有一条专门的命令：

```bash
lance prompt -f findings.json          # 打印真正会发出去的全文
lance prompt -f findings.json -check   # 只做词表自检，命中即 exit 1，可进 CI
```

改完词表先跑 `-check`，确认出站内容干净再连着跑 `loop`。

## 已知边界

- 没有并发：动作串行执行（现场一条一条来，便于判读和中断）
- LLM 模式单轮超时 60s，两次解析失败即报错退出，由调用方回落 rules
- 不做缺陷判定，也不做报告生成 —— 那是 litmus2 和人工的活

## 与 litmus2 的关系

**不是替代，是串联。** litmus2 可以单独交给客户（零 AI、可审计、单文件）；
lance 是你自己用的调度台，可以留在自己机器上，只把 action JSON 递进去。
